# gfx950 Flash Attention

Use the [pinned Rust toolchain and components](../../docs/getting-started.md#requirements).
Compilation was tested with ROCm 7.2.4 LLVM tools (`clang`, `llvm-link`,
`ld.lld`, `llvm-objdump`, `llvm-readobj`) and its AMDGPU device bitcode.
Numerical GPU execution additionally requires the HIP/HSA runtimes from that
installation and a gfx950 Wave64 device. The runner uses `ROCM_PATH`, defaulting
to `/opt/rocm`; point it at the ROCm 7.2.4 installation being used. This is the
tested ROCm configuration for this candidate.

The same BF16 Q/K, F32 value/accumulation, masking, full numerical reference,
144-byte ABI and Wave64/WG64 contract can be compiled for gfx950:

```bash
FE2O3_EXAMPLE_COMPILE_ONLY=1 bash examples/flash_attention_general_v1/run-gfx950.sh tile
FE2O3_EXAMPLE_COMPILE_ONLY=1 bash examples/flash_attention_general_v1/run-gfx950.sh simt
```

Remove the compile-only assignment for the corresponding numerical GPU run.
The runner declares gfx950; the host rejects another processor or wave size.
Compilation is not GPU qualification. This public candidate has no fresh GPU
execution result. gfx942 retains its existing runner; gfx942 GPU validation is
pending.
The gfx950 tile path requires actual BF16 MFMA instructions; SIMT rejects
matrix instructions. The runner retains LLVM, binding, ISA and code-object notes.
