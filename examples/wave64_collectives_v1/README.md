# Wave64 collectives V1

This standalone example owns the ordinary attributed source, finite-F32 CPU
oracle, formal model, and reviewed source/CPU correspondence for one fixed masked
Wave64 sum reduction plus inclusive and exclusive scans. The kernel is ordinary
Rust carrying `#[kernel(typed, ...)]`; the algorithm is not generated by
`macro_rules!`.

## Exact contract

- The launch shape is exactly `64x1x1` and all 64 physical lanes execute every
  collective convergently.
- One explicit `u64` selects logical participation. An inactive lane
  contributes `+0.0` and publishes `+0.0` in all three output allocations.
- An active lane publishes the complete masked reduction, the prefix including
  its value, and the prefix excluding its value. Prefix order is physical lane
  order, including across sparse masks.
- The empty mask is accepted and every output bit pattern is positive zero.
- The CPU oracle admits only finite integral `f32` values in `[-1024, 1024]`.
  Every possible 64-lane sum is therefore an exactly representable binary32
  integer, independent of the device reduction tree.
- Input and all three output extents must be exactly 64. The oracle validates
  every extent and input before mutating any output.

## Formal evidence

The Verus model uses mathematical integers. A recursive bit-value function
binds a 64-element logical activity sequence to a concrete `u64`, then proves:

- lane bounds and identity ownership injectivity;
- inactive-lane contribution and output exclusion;
- masked reduction recurrence and the full reduction result;
- active inclusive/exclusive scan recurrence; and
- the accepted empty-mask zero result.

Expected-negative proofs independently mutate bounds, activity exclusion,
ownership, reduction, and scan recurrence. The runner pins the Verus executable
version and digest, verifies the repository's authenticated release closure,
audits proof source, requires the positive summary, and requires every mutation
to fail.

## Reviewed attributed-source-to-CPU correspondence

`src/source_model_correspondence.rs` closes one narrower review gap without
claiming semantic Rust refinement. A `syn` collector parses the entire ordinary
attributed kernel and compares its complete syntax tree, after removing only
documentation attributes, with an independently encoded exact shape. It is not
a digest or keyword scanner: attributes, signature and types, guard predicates,
mask selection, lane indexing, collective call order and operands, inactive
values, publication sources, and all three ownership writes must be exact.
Hostile tests preserve the familiar collective and output names while mutating
each of those properties; every mutation rejects. Whitespace and non-doc
comments remain irrelevant.

Only after exact structural admission, an executable abstract interpreter
selects bit `lane` of the `u64` mask, accumulates the reduction and
inclusive/exclusive recurrences in increasing physical-lane order, publishes
bit-exact positive zero for inactive lanes, and assigns each output index to the
same physical lane. On the finite integral binary32 corpus, tests compare this
model with the independent CPU oracle over 4,359 masks for each of four input
families. Active signed zero is compared by integer value; inactive zero remains
bit exact.

- reviewed correspondence: `9d009122b179b15a2aab987404f1589611b171742bc1b3f1e98163245a53f48e`.

`verus/wave64_attributed_source_cpu_correspondence_v2.rs` separately defines

inactive publication, and injective same-lane ownership. Six expected-negative

correspondence identity, and outer commit.

This remains a reviewed structural correspondence. Both executable and formal
receipts keep `proves_source_to_model_refinement=false` because no theorem gives
Rust syntax an operational semantics and connects that semantics to the model.

## Checked 8x8 output-tile variant

The opt-in `tile-kernel` feature selects `src/tiled_kernel.rs` alongside the
unchanged default SIMT source. All three outputs use
`DisjointSlice<f32, Tiled2D<Index1D, 64, 8, 8, 1>>`, one checked tile witness,
and `get_tiled_2d_mut(&tile, 0, 8, 8, 8)`. Physical lane `lane` owns coordinate
`(lane / 8, lane % 8)` and therefore flat output index `lane` in each distinct
allocation. The mask, input and output guards, three convergent collective
calls, arithmetic, and inactive positive-zero publication remain unchanged.
This is structured output ownership; collective arithmetic remains explicit.

commit. The original checker, committed-tree check, mutation cases, source
identities and Verus proofs remain unchanged. The original 13-obligation

## Boundary

The reviewed structural relation does not prove semantic source-to-model
refinement. No current source-model-to-Kernel-IR relation is supplied.
It does not prove compiler causality.
Device compilation must use the one general production transaction and its
actual semantic MIR/SSA and Kernel IR. Unsupported behavior is terminal; there
is no workload-profile fallback. Host model tests do not qualify that device path.
It does not prove LLVM/ISA refinement.
It grants no artifact authority and grants no protected-execution authority.
It does not establish generalized safety, including memory safety or race
freedom, and cannot promote a parity row by itself.

Public issue #117 contains a historical protected `gfx942` observation for an
earlier exact receipt and a later compiler/finalizer checkpoint that records no
protected GPU result. The current configured finalizer test remains ignored
with `requires the measured direct LLVM/LLD worker built for gfx942`. The former
Worker V2 host/HSA lifecycle and its protected hardware launcher have been
deleted. Production execution must use the workload-neutral Worker V3 route;
Wave64 hardware execution through that route remains pending.
The bounded worker uses target-machine emission and the in-process LLD library API.
No COMGR path or shell invocation of `clang`, `llc`, or `ld.lld` is introduced
by this proof.
